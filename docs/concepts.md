# 概念

## 节点（node）

流水线里的一步。有 id、依赖、输入、产出。

## 角色（role）

**不是某个 Agent，是一种职责。** 角色声明能力档，你的配置决定谁上。

```
角色 dev_be（medium）  ←→  你的机器：zcode
                         同事的机器：claude
```

这就是为什么这套流程可以被分享：能被共享的是**结构**，不能共享的是**你装了什么**。

## 能力档（tier）

| 档 | 用来干什么 | 判据 |
|---|---|---|
| `high` | 判断、归因、抽象、写判据 | 结果错了会乘以多 |
| `medium` | 按骨架填空 | 有明确输入输出 |
| `low` | 格式强约束的机械活 | 对错可机器判定 |

**关键**：弱模型最擅长填空，最不擅长定结构。所以 `high` 档的产出必须是 `medium` 档能直接消费的形式——这就是"骨架先行"的由来。

## 人工闸门（gate）

**只有两个**：需求冻结、契约冻结。

判据是"错了会乘以几"：

- 需求冻结错了 → 四份下游工作全错
- 契约冻结错了 → 两边实现打架
- 其他任何一站错了 → 一个站重跑

所以别加闸门。加闸门是最容易的优化，也是最贵的优化。

## 交接物（handoff）

**只走文件，不走对话。**

每一棒的输入是上一棒落盘的 markdown，不是上一棒的对话历史。

三个后果：

1. 上下文不串味（实现者不会去猜设计者的心理活动）
2. 可回放（每步都能 diff）
3. 可换人（同一份文件喂给任何模型都成立）

## 冷启动（cold start）

每个角色一个全新会话，只喂交接物。

这在 A 档（多 Agent）是自然发生的，在 C 档（单 Agent）**必须刻意执行**——否则同一个模型会带着"我刚设计的方案"去实现和评审，然后全程自我确认。

## 盲写（blind）

E2E 用例站在开发**之前**，且不许读代码。

因为用例一旦看过实现，就会对齐"实现做了什么"，而不是"范围要求什么"。那一刻它就不再是裁判。

副产品很有价值：**写不出用例 = 设计有洞**，而且是在花掉四个站的算力之前就知道。

## 偏离（deviation）

实现与契约不一致时，必须落盘登记。

不登记就改，会让契约和评审**同时**失效——评审照着契约看代码，看到的全是"错误"；而契约本身也不知道自己已经过时了。

## 止损（stop-loss）

- 修复循环最多 2 轮
- 同类问题第 2 次红 → **回契约站，不回开发站**

因为同类问题重复出现，说明不是实现马虎，是判据本身错了。

## 能力档退化（A / B / C）

| 档 | 不同 Agent 数 | 变化 |
|---|---|---|
| A | ≥3 | 全流程 |
| B | 2 | 用 model/effort 拉开强弱 |
| C | 1 | 冷启动分饰，跳过交叉互审 |

**C 档必须如实标注"未做交叉评审"。** 假装做了，比承认没做危险得多。
