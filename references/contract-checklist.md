# 契约清单（八项）

03 站逐条打勾，缺一项不许放行。这不是"参考"，是**准入条件**。

## 1. 数据模型与枚举全集

- [ ] 每个接口的请求/响应字段，类型精确到可生成 schema
- [ ] 所有枚举列出**全部**取值，含「其他/未知」的处理
- [ ] 可空字段明确标注，非空字段明确标注
- [ ] 新增表/字段的迁移脚本位置已定

## 2. 错误码

- [ ] 业务错误码与 HTTP 状态码的映射表
- [ ] 前端如何按码分支（哪几个码要单独提示）
- [ ] 未预料错误的兜底码

## 3. 鉴权与权限

- [ ] token 放哪里（header / cookie / 参数）
- [ ] 无权限时返回 403 还是 404（**必须统一，这是最常见的 E2E 红灯**）
- [ ] 越权访问他人资源时的行为

## 4. 分页与排序

- [ ] 分页参数名、默认值、上限
- [ ] 排序字段白名单（防注入）
- [ ] 无数据时返回空数组还是 404

## 5. 格式

- [ ] 时间统一 **ISO 8601 字符串**（带时区），不用 unix 秒
- [ ] 金额用整数分还是字符串小数，明确
- [ ] ID 用 string 还是 number（**统一 string**，避免前端精度丢失）

## 6. 空值语义

- [ ] 区分三种情况：字段为 `null` / 字段不存在 / 空数组 `[]`
- [ ] 前端对三种情况的渲染分别是什么
- [ ] 「没有值」和「值就是空」不许混为一谈

## 7. 幂等与并发

- [ ] 重复提交的判定键（幂等 key 或业务唯一键）
- [ ] 并发修改同一条记录的行为（乐观锁版本号 / 后写覆盖）
- [ ] 并发冲突时返回什么

## 8. 取消、超时、重试

- [ ] 接口超时时间
- [ ] 长任务能否取消，取消后资源如何回收
- [ ] 哪些接口可以安全重试（幂等），哪些绝对不行
