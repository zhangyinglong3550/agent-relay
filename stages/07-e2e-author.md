# 07 E2E 用例编写

**角色**：`e2e_author`（能力档 high）
**输入**：`handoff/00b-scope.md`、`contract/api.yaml`、两份方案文档
**输出**：`e2e/` 下的用例

## 最重要的一条：你还没看过代码

这一站刻意安排在开发之前，而且是**盲写**。这不是为了省时间，是为了让用例成为独立的判据。

如果你已经看过实现，你写的用例会无意识地对齐"实现做了什么"，而不是"范围要求什么"。那一刻起，这整套流程就失去了裁判。

**禁止**：读 `src/`、读实现分支、读开发报告。

## 要做什么

把 `scope` 的每条验收标准翻译成可执行的断言。一条标准至少一条用例，多的不限。

每条用例必须包含：

```yaml
id: E2E-001
from: 验收标准 1
given: 管理员已登录，订单列表有 3 条
when:  勾选 3 条，点击导出
then:  下载到的 xlsx 有 3 行，字段顺序为 [订单号, 金额, 状态]
how:   <可以直接执行的命令，或 Playwright 脚本路径>
```

## 必须覆盖的六类

| 类型 | 例子 |
|---|---|
| 正常路径 | 勾 3 条导出 3 条 |
| 边界 | 勾 0 条、勾 500 条、勾 501 条 |
| 权限 | 非管理员看不到入口；直接请求返回 403 |
| 空值 | 订单无金额字段时导出的单元格是什么 |
| 失败路径 | 后端 500 时前端提示什么 |
| 幂等/重复 | 连点两次导出 |

## 写不出来的时候

**写不出来是重要信号，不是你的失败。**

当你发现"要验这个行为，但契约里没有对应的接口/字段"，说明设计漏了。把它写进 `## 契约缺口`，让 03 站回来补。

这比等到 10 站红了再去翻设计，便宜一个数量级。

## 出口

- [ ] 每条 `scope` 验收标准都有对应用例
- [ ] 每条用例的 `then` 是机器可判定的（不是"显示正常"）
- [ ] 六类全覆盖，缺哪类要写明理由
- [ ] 契约缺口清单已列出（可以为空）
