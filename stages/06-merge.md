# 06 合并

**角色**：`dev_be`（能力层 medium，由后端主导）
**输入**：前端开发分支、后端开发分支
**输出**：集成分支 + `handoff/06-merge.md`

## 为什么由后端主导

冲突多发生在契约侧——路由、字段、错误码。前端对冲突的典型解法是"加个适配层"，那正好把契约不一致藏起来，等到 E2E 才炸。

## 要做什么

1. 建集成分支（默认 `relay/<feature>-integration`）
2. 依次合入两侧，**一次只合一侧**，每合一次跑一次冒烟
3. 冲突处理**必须遵守契约**，不许"以我为准"
4. 冒烟：构建 + 类型检查 + 启动一次，确认能起来
5. 把两侧的偏离记录**合并成一份**，标出互相冲突的偏离

## 冲突裁决顺序

1. `contract/api.yaml`
2. `handoff/00b-scope.md` 的验收标准
3. 两侧方案文档
4. **都没有规定时，停下来问人，不要自己发明**

## 出口

- [ ] 集成分支能构建、能启动
- [ ] 两侧的偏离记录已合并，冲突项已标出
- [ ] 没有任何一边的代码被"临时注释掉以通过构建"
- [ ] 合并后的 diff 里，没有出现契约之外的新接口

## 产物格式

```markdown
# 合并记录

- 集成分支：relay/order-export-integration
- 合并顺序：backend → frontend
- 冲突：3 处（1 处按契约裁决，2 处需人工确认）
- 冒烟：build ✓  typecheck ✓  start ✓
- 合并后的偏离：见下
```
