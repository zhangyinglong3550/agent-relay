# 00b 需求冻结 ⛩

**类型**：人工闸门
**输入**：`handoff/00a-assumptions.md`
**输出**：`handoff/00b-scope.md`

人工闸门在 `plain` runner 里会停下来等回车；在 `orca` runner 里是一个等你的 Task。

## 要做什么

把澄清结果**锁死**成一份范围文件。澄清只记录，冻结才承诺——这两件事分开做，否则你会边问边缩范围，最后得到一个又小又不清楚的东西。

## 这份文件必须包含

1. **一句话目标**：谁在什么场景下得到什么
2. **范围内**：按优先级列出的条目
3. **不做清单**：至少 3 条，且每条写明"为什么这次不做"
4. **验收标准**：每条都能被第三方独立判定

第 4 条最狠：如果一条标准需要"看着感觉对不对"，它就不是验收标准。改写它，或者删掉。

## 自检

- [ ] 不做清单 ≥ 3 条
- [ ] 每条验收标准都能翻译成一条自动化断言
- [ ] 没有任何「视情况而定」
- [ ] 没有把"技术方案"写进来（那是 01/02 的活）

## 不合格的信号

- 全文没有出现"不做"两个字
- 验收标准里出现"良好""合理""友好""尽量"
- 你能感觉到自己还没想清楚，但想先跑起来看看——**这是最贵的偷懒**

## 产物格式

```markdown
# 范围：订单列表批量导出

## 目标
运营同学在订单列表页，把勾选的订单导出为 Excel，不再手工复制。

## 范围内
1. 勾选导出（当前页）
2. 导出上限 500 条，超出提示
3. 仅管理员可见入口

## 不做（这次）
- 全选所有页：需要异步任务表，成本翻倍，且运营没提
- 导出 PDF：没有已知用途
- 导出历史记录：留到有第二个用户时再说

## 验收标准
1. 管理员勾选 3 条导出，得到 3 行数据的 xlsx，字段顺序固定
2. 非管理员看不到入口；直接请求接口返回 403
3. 勾选 501 条时，前端拦截并提示，不发请求
```
